## Zależności i testy
Manifesty niezmienione. Potwierdzono SHA-256 wszystkich 19 plików vendor i obu
plików Marked. Metadane wheels pokazują zgodny deklarowany zestaw Windows cp313;
nie oznacza to wykonania natywnych modułów Windows na Linux.

Pierwsza próba testów: brak FastAPI w środowisku, błędy importu. Utworzono
oddzielne QA, wykorzystano lokalne pure Python wheels i istniejące natywne
biblioteki Linux. Paczki projektu nie zmieniono w celu dopasowania do QA.
Python 3.12.14, SQLite 3.53.1, Pydantic 2.14.1 i Pillow 12.3.0 różnią się od locka Windows.

Bazowo: 72 Python + 29 JS zaliczone, 4 Windows pominięte.
Po implementacji: 77 Python + 33 JS zaliczone, 4 Windows pominięte, brak niepowodzeń.
Testy używają prawdziwego SQLite, HTTP/SSE, dekoderów i procesów; model inference
i nowe metadane/pobrania PyPI są kontrolowane. Nowe testy obejmują offline po
pobraniu, błąd sieci/retry, niezgodny hash/host, uszkodzony lokalny cache,
kolorowanie, kopiowanie, częściowy stream i fallback renderera.
Dosłowne logi: WYNIKI_TESTOW.txt (ostatnia sekcja).

NIE URUCHOMIONO: Windows/CUDA/VRAM, PowerShell, natywny instalator/ACL/Job Object,
System.Speech, mikrofon i uninstall. Playwright nie wystartował z powodu braku
binarium przeglądarki. Brak wizualnego odbioru. Nie pobierano modeli ani całego
vendor z upstream; poprawność nowej ścieżki Windows pozostaje do sprawdzenia.

## Wykonana kontynuacja
Najmniejszy domykający istniejący interfejs moduł: podstawowe lokalne kolorowanie
kodu, bez nowej biblioteki i bez zwiększenia VRAM. Równolegle przygotowano źródła
do synchronizacji bez binariów: prywatny Python i brakujące wheels są pobierane
po przypiętej nazwie i SHA. Pełny ZIP nadal zawiera niezmienione vendor.
Nie przepisano backendu, nie zmieniono schematu ani modeli.
